# Syn xử lý file, 2026-10-30

**Trạng thái:** thiết kế để review. Chưa có dòng code nào viết theo nó.

**Đã đo:** dung lượng tải của bộ gói, gói nào có bản chạy được trên Pyodide, đường đi của tool trong code hiện tại.
**Chưa đo:** chưa lần nào chạy Pyodide, cả trong Node lẫn trong WebView. Thời gian khởi động, RAM, tốc độ và việc các
thư viện có chạy thật không đều do Bước 0 trả lời (§14). Mọi con số đề xuất trong tài liệu được đánh dấu *tạm*.

**Phạm vi:** desktop trước. Android và model nhỏ có tầng Rust, không có Python.

---

## 1. Tóm tắt

Syn được thêm ba thứ:

1. **Một lối đưa file vào chat.** Nút chọn file, kéo thả, hoặc thư mục đã duyệt. Quyền đọc do Rust cấp, model chỉ
   thấy handle `f1`, `f2`.
2. **Một tầng đọc có cấu trúc bằng Rust**, chạy ở mọi nơi, không cần model viết code.
3. **Một máy Python không có I/O** (`run_python`), chạy Pyodide trong WebView cách ly. Syn chạy code tùy ý trong đó
   mà không phải hỏi từng lần, vì code không chạm được mạng, đĩa, vault hay app.

Syn vẫn **không có shell**. Không ghi đè file. Nội dung file vẫn là lời người ngoài. Bộ gói Python tải riêng, khoảng
**90 MB**, chỉ khi người dùng đồng ý.

```
           kéo thả ── byte ──┐
 nút chọn (hộp thoại Rust) ──┼─► đính kèm f1, f2 ─┬─► tầng Rust ───► bảng r1 ─► crunch, show_visual
 thư mục đã duyệt ───────────┘                    │                  tài liệu ─► model
                                                  ├─► look_at_file ─► ảnh trang ─► model có vision
                                                  └─► run_python ─┬─► bảng r3
                                                     (không mạng, ├─► ảnh trong chat
                                                      không đĩa)  └─► o1 ─► Rust kiểm ─► file MỚI trong vault
```

| # | Quyết định | Đề xuất | Cái giá |
|---|---|---|---|
| D1 | Python không I/O thay vì shell thật | **Có** | Không chạy được ffmpeg, LibreOffice; không cài thêm thư viện (§13) |
| D2 | Bộ gói ~90 MB tải khi dùng lần đầu, không gộp vào bản cài | **Có** | Lần đầu cần mạng và một bước đồng ý |
| D3 | Bộ gói gồm cả thống kê và dữ liệu lớn, không chia nhỏ | **Có** | Thêm ~44 MB so với bộ tối thiểu (§8.3) |

| D6 | Thiếu điều kiện trên macOS 13.3: tắt tính năng trên máy đó, không nâng sàn của app | **Có** | Máy đó chỉ có tầng Rust |

## 2. "Ngang" nghĩa là gì

Ba sản phẩm kia mạnh về file vì **viết và chạy được code**, không phải vì danh sách định dạng dài. Codex có skill đọc
và tạo PDF, bảng tính, Word trên sandbox hệ thống. Cowork làm việc trong thư mục được nối, có skill PDF, DOCX, PPTX,
XLSX. Thêm từng parser bằng Rust sẽ không bao giờ đuổi kịp, nên phải có máy chạy code.

## 4. Trải nghiệm

**Đưa file vào.** Người dùng kéo `sao-ke.xlsx` vào ô chat. Một thẻ nhỏ hiện tên, cỡ, nút bỏ. Gửi đi, file được đọc
tại chỗ, không chép vào vault, không vào Files.

**Khi Syn chạy Python.** Trong câu trả lời có một bước "Đang chạy Python", mở ra thấy code và stdout. Có nút dừng
chung của run. Bảng và ảnh hiện ngay dưới câu trả lời. "Cách tính" trong `HowWorkedOut` có thêm bước này.

**Khi Syn làm ra file.** Một thẻ hiện tên, cỡ, ô xem trước, nút **Lưu vào vault** và **Tải về**. Chưa bấm thì file chỉ
nằm trong bộ đệm. Câu trả lời không được nói "đã lưu" khi chưa lưu (`syn.claims-match-tools`).

**Lần đầu cần Python.** Syn hỏi bằng một thẻ, không tự tải:

> Việc này cần bộ phân tích dữ liệu (khoảng 90 MB, tải một lần, chạy hoàn toàn trên máy). **Tải** · **Để sau**

Chọn "Để sau", Syn làm bằng tầng Rust nếu được, và nói thẳng phần nào không làm được.

**Khi không làm được.** Syn nói rõ lý do và lối khác. Ví dụ: "File này là bản scan mà model đang dùng không đọc được
ảnh. Đổi sang model có vision, hoặc gửi bản có chữ."

**Cài đặt.** Trong Syn có công tắc "Chạy phân tích trong sandbox", dung lượng đã dùng, nút xóa bộ gói. Trên điện thoại
không hiện.

## 5. Đính kèm

### 5.1 Lối vào

| Lối vào | Ai cấp quyền | Rust giữ gì |
|---|---|---|
| Nút đính kèm | Lệnh `syn_attach_pick` mở `ask_open`, không nhận tham số đường dẫn | Đường dẫn và hash |
| Kéo thả, dán | Trang gửi **byte** qua raw IPC | Bản chép trong bộ đệm |
| Thư mục | Thẻ duyệt, đóng dấu theo hội thoại | Thư mục |
| File trong vault, nguồn file | `spreadsheet_at` đã kiểm | Node id |

**Vì sao kéo thả gửi byte.** `dragDropEnabled` đang tắt, trang không có đường dẫn. Trang chỉ đưa được thứ nó đang giữ,
không xin được quyền đọc thứ khác. Đó cũng là tinh thần của `dialogs.rs` và commit `02301f82`.

### 5.2 Dữ liệu

```sql
CREATE TABLE IF NOT EXISTS state.attachments (
  scope      TEXT NOT NULL,     -- crunch::scope_for: hội thoại, không có thì run
  handle     TEXT NOT NULL,     -- f1, f2…
  name       TEXT NOT NULL,
  ext        TEXT NOT NULL,
  bytes      INTEGER NOT NULL,
  sha256     TEXT NOT NULL,
  kind       TEXT NOT NULL,     -- 'path' | 'copy' | 'folder' | 'node'
  location   TEXT NOT NULL,     -- đường dẫn, hoặc đường dẫn trong bộ đệm, hoặc node id
  created_at INTEGER NOT NULL,
  PRIMARY KEY (scope, handle)
);
```

Model chỉ thấy `handle`, `name`, `ext`, `bytes`. Không thấy `location`.

**Quy tắc:**
- `state.db` không sync. Mở hội thoại ở máy khác thì `f1` trả lỗi "file này ở máy khác".
- File đổi sau khi chọn: đọc bản mới, báo model hash đã đổi. File mất: báo lỗi, không đoán.
- File được chọn trong thư mục đã duyệt phải nằm ngay trong thư mục đó sau khi `canonicalize`, không qua symlink ra
  ngoài. Quy tắc như `folder.watch`.
- Bộ đệm nằm ngoài vault, xóa khi xóa hội thoại (`delete_conversation` gọi thêm) và sau 30 ngày *tạm*.
- Bảng `r1` vẫn hết hạn sau 24 giờ như cũ. Hội thoại mở lại hôm sau đọc lại từ `f1`, không phải chọn lại file.
- Giới hạn: bảng tính 50 MB như cũ, file khác 256 MB như `file_text::MAX_FILE`.

### 5.3 Tool

- `read_spreadsheet`, `read_file_text`: nhận thêm handle `f1`. `read_file_text` hôm nay chỉ đọc chữ đã index; với
  đính kèm thì đọc tại chỗ, không index.
- `list_folder { folder, pattern }`: liệt kê thư mục đã duyệt, trả thêm `f` cho từng file được chọn.
- `folder.watch` thêm decoder xlsx dùng lại `spreadsheet.rs`. `web.rs` nhận `text/csv` và trả bảng có handle.

Không thêm tool đọc nào khác. Mỗi khai báo tốn token ở mọi lượt (`toolset.rs`).

## 6. Tầng Rust

`syn/document.rs` mới, tách khỏi `file_text.rs`. Kết quả có hai dạng, có phân trang:

```jsonc
// bảng, đi qua resultset như read_spreadsheet
{ "table": { "handle": "r2", "rows": 1204, "columns": ["..."] }, "sample": ["..."] }
// tài liệu
{ "kind": "pptx", "sections": [{ "at": "slide 3", "heading": "...", "text": "...", "tables": ["r3"] }], "next": "slide 4" }
```

| Định dạng | Cách làm |
|---|---|
| json, jsonl | `resultset::from_objects` khi là danh sách bản ghi; còn lại trả chữ |
| docx | `zip` + đọc `word/document.xml` theo phần tử; mỗi bảng con thành một `r` |
| pptx | `zip` + từng `slideN.xml` và `notesSlideN.xml`, đúng thứ tự trong `presentation.xml` |
| html | Bóc bằng parser; mỗi `<table>` đều thành `r` |
| eml | Parser MIME; đính kèm thành `f` mới dạng `copy` |
| zip | Liệt kê; lấy từng file thành `f` mới. Giới hạn tỉ lệ nén, tổng dung lượng, số file; không tự giải nén lồng |

Crate cho phần XML và MIME chọn lúc làm, theo đúng lệ của `Cargo.toml`: đo kích thước, ghi lý do. Thêm vào `crunch`:
`median`, `p90` (phân vị), `stddev`, `corr`, và stage `pivot`. Một số do Rust tính vẫn tốt hơn một số do Python tính khi
cả hai làm được, vì nó chạy cả ở nơi không có Python.

## 7. Nhìn và nghe

### 7.1 `look_at_file`

```jsonc
look_at_file { "file": "f1", "pages": "1-3" }   // tối đa 5 trang một lần *tạm*
```

Trang PDF dựng bằng `pdfjs-dist` trong trang app, ảnh thì thu nhỏ theo cạnh dài. Chỉ gửi khi `Capability.vision`. Tool
này `.outside()`: nội dung ảnh cũng là lời người ngoài.

**Phải kiểm ở Bước 0:** Anthropic đã gửi ảnh trong tool result. OpenAI và Gemini chưa được kiểm, mà eval chạy trên
`gpt-6-luna`. Nếu tool result không mang được ảnh, engine thêm một tin ngay sau đó, đánh dấu là nội dung file.

### 7.2 Số đọc bằng mắt

Số đọc từ ảnh **không có đảm bảo "do Rust tính"**. Bảng lập từ đó mang `Source { kind: "vision" }`, `HowWorkedOut` ghi
rõ, và câu trả lời phải nói đó là số đọc từ ảnh, cần đối chiếu.

### 7.3 Âm thanh, video

Không chạy Whisper cục bộ ở đợt này: tốn dung lượng và chỉ có ích khi không dùng được provider. Gửi tới provider làm
được, sau một thẻ nói rõ file sẽ rời máy. Provider không làm được thì nói không làm được. Làm sau cùng (PR 8).

## 8. `run_python`

### 8.1 Tool

```jsonc
run_python {
  "code": "df = pd.read_excel('/input/f1.xlsx')\nsynabit.table(df.groupby('Nhóm').sum(), 'theo_nhom')",
  "files": ["f1", "r2"],
  "timeout_s": 60                // mặc định 60, tối đa 300 *tạm*
}
// trả về
{
  "stdout": "...",               // cắt theo room::scaled, nói rõ khi bị cắt
  "error": null,                 // traceback, cắt bớt
  "tables": [{ "handle": "r3", "name": "theo_nhom", "rows": 12, "columns": ["..."] }],
  "images": [{ "id": "i1", "bytes": 48211 }],
  "outputs": [{ "id": "o1", "name": "bao-cao.xlsx", "bytes": 48211, "check": "ok" }],
  "restarted": false             // true: máy khởi động lại, biến cũ đã mất
}
```

Trong sandbox:
- `/input/`: file và bảng được đưa vào (`r2` thành `/input/r2.csv`, kèm kiểu cột).
- `/output/`: thứ gì nằm đây lúc kết thúc thì thành `o1`, `o2`.
- `synabit.table(df, name)`: đổ về bảng có handle, tối đa `resultset::MAX_ROWS`, quá thì nói rõ.
- `synabit.show(fig)`: đưa ảnh vào chat.

Bảng có `Exposure::Aggregates` **bị từ chối**: bảng đó hứa không cho dòng nào tới model, mà stdout thì in được mọi dòng.

### 8.2 Kiến trúc

```
engine ── How::RunPython ──► python.rs: tạo token, đợi oneshot, có hạn giờ
   │ phát sự kiện syn-python-run { token }
   ▼
SynPythonHost.vue (trang app, gắn như SynVisualLooker, ẩn)
   │ <iframe sandbox="allow-scripts" src="synpy://localhost/run/<token>">
   ▼
khung ──► Worker (blob) ──► Pyodide
   │  GET /pkg/*              ◄── file tĩnh đã kiểm chữ ký, trong thư mục dữ liệu app
   │  GET /input/<token>/<f>  ◄── Rust stream đúng file được cấp cho lần chạy này
   │  postMessage (transfer) kết quả, file ra ──► trang app
   ▼
trang app ── invoke syn_python_done (raw, kèm token) ──► Rust kiểm, nhả oneshot
```

**Scheme riêng `synpy`, không dùng chung `synvisual`.** Pyodide phải tải gói nên cần `connect-src` về chính nó. Nếu dùng
chung, code trong máy sẽ `fetch` được `/v/<id>` và đọc mọi hình đã giữ, mà hình có chứa dữ liệu cá nhân.

**CSP.** Như `visual/protocol.rs`, phải ghi tường minh cả hai cách viết origin, vì WebKit không khớp `'self'` trong khung
sandbox (Bước 0 của visuals, 2026-10-27):

```
default-src 'none';
script-src synpy: http://synpy.localhost 'wasm-unsafe-eval' 'unsafe-inline';
worker-src blob:;
connect-src synpy: http://synpy.localhost;
frame-ancestors <trang app>; form-action 'none'; base-uri 'none'
```

`connect-src` như trên cũng chặn cả IPC của Tauri đi qua scheme `ipc:`. Đây là cùng lý do `visual/protocol.rs` ghi trong
comment, và phải được trang tấn công chứng minh lại.

**Protocol `synpy`:**
- Chỉ GET. `/run/<token>`, `/pkg/*`, `/input/<token>/<tên>`, còn lại 404.
- `/input` chỉ phục vụ file đã cấp cho token đó, mỗi file một lần.
- Khung sandbox có origin mờ nên `fetch` cần CORS: chỉ trả `Access-Control-Allow-Origin: null`, chỉ cho `Origin: null`.
- Không ghi đường dẫn request ra log, vì đường dẫn là kênh duy nhất code có thể viết vào.

**Vì sao khung sandbox và Worker.** Origin mờ nghĩa là không có IndexedDB, cookie hay OPFS, nên không còn chỗ giấu dữ
liệu giữa hai hội thoại. Worker cho `terminate()`, cách dừng thật khi code chạy vòng lặp vô hạn.

**Phương án dự phòng** nếu blob Worker không chạy được trong khung trên WKWebView, WebView2 hay WebKitGTK: một cửa sổ
WebView ẩn riêng, label riêng. `gate::may_call` từ chối mọi lệnh với label lạ, đóng cửa sổ là dừng. Không dùng
`allow-same-origin`: như vậy có IndexedDB, mở lại đúng chỗ giấu dữ liệu vừa bỏ được.

**Đợi kết quả.** `look.rs` đợi 4 giây rồi bỏ qua. `run_python` đợi tới `timeout_s` cộng thời gian khởi động, hết giờ thì
`terminate` và trả lỗi. Nút dừng của run cũng `terminate`. Khung gửi về gì cũng chỉ là dữ liệu lạ: giới hạn cỡ như
`Lint::bounded`, token sai thì bỏ.

## 9. Đầu ra

**`save_output { output, path }`.** `Power::Write`, `.after_reading()`, `.locked_with("file")`. Chỉ tạo file mới, như
`write_spreadsheet`.

**Kiểm trước khi lưu, ở Rust:**
- Đuôi khớp nội dung, cấu trúc mở lại được.
- Không có macro (`vbaProject.bin`).
- xlsx: quét công thức (§10).
- docx, pptx: quét link ngoài và ảnh ngoài.

**Sửa file có sẵn.** Luôn tạo bản mới cạnh bản cũ, ví dụ `Báo cáo (Syn).xlsx`. Trong vault, người dùng có thể bấm thay
bản gốc, bản cũ vào thùng rác. File ngoài vault không bao giờ bị thay.

**Xem trước.**
- xlsx, csv: lưới, qua `read_spreadsheet`.
- docx: mammoth trong sandbox ra HTML, qua `dompurify`.
- PDF: `pdfjs-dist`.
- pptx: danh sách slide và chữ. Không có ảnh (§13).

**`write_spreadsheet` cho nơi không có Python.** Thêm định dạng số và biểu đồ. **Công thức chỉ được ghi khi run chưa
taint**, vì `spreadsheet.rs` cố ý ghi chuỗi trông như công thức thành chữ: tool này chạy được sau khi đọc nội dung lạ,
và một công thức có thể gửi ô bên cạnh ra ngoài ngay khi người dùng mở file.

**`show_visual` nhận handle.** Thêm `tables: ["r3"]`; hình đọc số qua `synabit.table("r3")` thay vì model chép tay vào
HTML. Rust đọc bảng và nhúng vào trang khi dựng, để bảng hết hạn thì hình đã giữ vẫn đúng. Quy định 120.000 ký tự chỉ
tính phần code. Việc này cũng làm giảm token của `vz-spending-vi`, hiện khoảng 50K.

**Giữ thành Rich Table.** Thêm nút trên bảng kết quả: tạo ghi chú chứa Rich Table từ `r3`. Đó là cách rẻ nhất để có biểu
đồ tự cập nhật, và `resultset.rs` đã nói việc này do người dùng quyết định.

| Mối đe dọa | Chặn bằng | Kiểm bằng |
|---|---|---|

| File làm ra gửi dữ liệu đi khi mở | Quét trước khi lưu (dưới đây) | Test |
| Bộ gói bị tráo | Chữ ký và hash, Rust kiểm | Test chữ ký sai |
| Kết quả giả từ khung | Token; coi là dữ liệu lạ; giới hạn cỡ | Test |
| Bộ đệm lộ qua sync | Ngoài vault | Test đường dẫn |

**Taint.** Engine đặt taint cho `run_python`, như `browse`:
- Run bị taint khi có đầu vào là file, hoặc máy đã từng nhận file trong hội thoại này. Trạng thái này **dính vào máy**,
  vì biến trong máy vẫn còn nội dung lạ dù run sau không đưa file mới vào.
- Chỉ đưa vào bảng `r` thì không tự thêm taint: nguồn của bảng đã tính taint rồi, như `compute`.
- Dòng trong `policy.rs`: `.app_only().no_helper().locked_with("file")`. `Power::Read`, vì không có cạnh nào ra ngoài,
  giống `compute`.

**File làm ra.** Run đã taint: **từ chối lưu** xlsx có `HYPERLINK`, `WEBSERVICE`, `IMPORT*`, DDE hay link ngoài, và docx,
pptx có link hay ảnh ngoài. Run chưa taint: cảnh báo trên thẻ. Luôn từ chối macro.

**Log.** Code được giữ trong log tool để `HowWorkedOut` hiện lại, nhưng log hội thoại nằm trong vault và có sync, mà code
có thể chứa dữ liệu. Nên `compact` giữ tối đa 8.000 ký tự *tạm*; stdout chỉ giữ phần xem trước như các tool khác.

**Thêm vào `contracts/invariants.json`:**
- `syn.python-has-no-door`: máy Python không tới được mạng, đĩa, IPC.
- `syn.attachment-from-dialog`: quyền đọc file lẻ chỉ đến từ hộp thoại của Rust, hoặc byte trang đang giữ.
- `syn.file-output-never-overwrites`: `save_output` không bao giờ ghi đè.

## 15. Câu hỏi còn mở

Không chặn việc duyệt, nhưng nên biết:

1. **Chất lượng bảng PDF** với sao kê ngân hàng Việt Nam thật. Chưa có dữ liệu. Nếu kém, phải thêm hình mẫu riêng hoặc
   đi đường `look_at_file`.
2. **Tiếng Việt trong file tạo ra.** matplotlib và reportlab cần font có dấu; bộ gói phải kèm font, chưa tính trong 90 MB.
3. **Có nên cho Telegram và routine dùng Python không.** Đợt đầu không, vì cần WebView đang sống.
4. **Một máy chạy cùng lúc có đủ không**, khi hai hội thoại cùng phân tích.
5. **Tốn token.** Model viết code rồi tự sửa lỗi có thể tốn hơn `crunch` nhiều. Eval sẽ cho số.
